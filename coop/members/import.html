C15 · From note 05's draft services (UI-35). A CSV of members, imported all or nothing (import_members). Every row is checked first. If any row fails, nothing is saved and every problem is listed as row, column and message, so the file is fixed in one go. The check is the service's dry_run. Up to 5,000 rows, UTF-8 with or without a BOM.

Errors (05): a row without an ID number; an ID or member number already in the register; one that appears twice in the file; an unknown cluster or area; an area name used in more than one place and written without its parent. An existing ID is an error in v1, so an import only ever adds (05, to decide 3).

Status gating (01): refused while the cooperative is on hold or ended. While onboarding it's the usual way to load the register. Only Administrators and Managers import (members.manage). Each new member's first status change has the source "Imported".

The file in this mockup is made up of new people, named from the shared data. Its problem rows point at real members, clusters and areas, so the messages match what the register holds.
